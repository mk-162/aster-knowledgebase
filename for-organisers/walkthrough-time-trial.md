# Walkthrough: a time trial

In a time trial (TT), athletes start **one at a time** and each races their
**own clock**. The fastest elapsed time wins. This walkthrough covers
setting one up and getting the most from split times.

## 1. Create the event as a "Time trial"

Choose the **Time trial** card when you [create the event](create-an-event.md).
Each athlete's clock starts when they physically cross the start line, not
on a shared gun, and the results are ranked fastest-first.

## 2. Route, start and finish

[Build or upload your route](routes-start-and-finish.md) and set the
**start** and **finish** lines. The start line matters more here than in a mass start,
because each athlete's time begins the moment they cross it. Place it where
athletes are up to speed and the line is unambiguous.

## 3. Splits with checkpoints

To get **split times** (and let spectators compare athletes section by
section), add checkpoints along the course. Splits make a TT far richer to
follow: viewers can see who's fastest on the climb versus the flat. See
[Comparing riders](../for-spectators/comparing-riders.md).

## 4. Categories and start order

Add your [categories](registration-and-categories.md). TTs are usually run
as a start list, with athletes setting off at intervals, so think about your
start order and, if you use waves, set **wave start times** per category.

## 5. On the day

- Athletes **start individually** and are timed from their own start
  crossing.
- They're **finished automatically** at the finish line.
- The leaderboard ranks by **fastest elapsed time**, and gaps compare each
  athlete's own time, so someone who started later can still top the board.
- Watch for **alerts** as usual: see
  [Handling alerts](handling-sos-alerts.md).
- If an athlete's start crossing was missed or wrong, you can **set their
  start time by hand** from the roster. It's the one-field recourse for a
  disputed start. See
  [Running the event on race day](race-day-management.md).

## 6. After: results

[Publish results](results.md), ranked by time within each category, and
export a CSV. Publishing works from whatever timing data you've recorded;
chip times can be brought in through Aster's results integration if you use
timing kit.

## Things to get right

- **Start-line placement is the timing point.** Each athlete's clock begins
  at the start crossing, so make the line clean and consistent for everyone.
- **Use checkpoints for splits.** They turn a TT from a single number into a
  segment-by-segment story for spectators.
- **Elapsed time, not finish order, decides it.** The first person to
  physically finish isn't necessarily the winner; the fastest time is.
